# NPU Detect

仓库：https://github.com/cocobronie2333-dot/npu-detect

## 获取应用

在用户指定的应用目录执行 `git clone https://github.com/cocobronie2333-dot/npu-detect.git`。已有同仓库 checkout 时复用，仅在工作区干净时 `git pull --ff-only`，不覆盖用户修改。

需要 Git、Python 3.10+，远端需要 `npu-smi`。在应用目录创建 `.venv`，使用虚拟环境 Python 执行 `-m pip install -r requirements.txt`，不依赖开发者机器的路径。

## 生成机器配置

读取本次任务用户提供的 SSH 信息或用户指定的凭据文件。遵守已有的凭据来源和生成文件位置约定。缺少必要字段时询问，不猜测密码或类别。

当前应用支持 IPv4、默认 SSH 端口 22，以及密码或本机 SSH 私钥路径；不支持自定义端口。私钥路径必须是本机已有文件的绝对路径。

将配置保存为仓库外的 UTF-8 JSON；用 JSON 序列化器写入，最多 64 台机器：

```json
{"hosts": [{"ip": "192.0.2.10", "username": "example", "password": "user-provided-password", "category": "A5"}]}
```

公钥认证可使用 `{"ip":"192.0.2.10","username":"example","password":"","key_path":"本机私钥绝对路径","category":"A5"}`。密码留空时，应用以私钥登录，并使用无交互 `sudo` 运行 `npu-smi`；非 root 账号若仍需 sudo 密码，必须另行配置合法的无密码 sudo 权限或提供密码。保留旧密码会让 SSH 在密钥失效时尝试密码，并将其用于 sudo，因此密码更改后要清空或更新旧密码。

类别可为 A3、A5 或不超过 40 字符的自定义名称，缺省归入“未分类”。不要覆盖已有凭据文件，除非用户要求更新；可选择新文件。真实配置不得写入技能、提交到 Git 或打印到日志和回复中。

## 配置 SSH 公钥登录

网页的“一键检测 NPU”在新增机器检测成功后显示其 SSH 主机指纹。用户确认指纹后，应用才生成或复用该 IP 对应的 Ed25519 密钥、安装公钥、验证仅私钥登录，并把 `key_path` 保存到配置；密码字段继续保留。检测失败、取消指纹确认或指纹变化时不安装公钥。指纹若不能从可信渠道核对，应明确告知首次连接信任的风险，不把扫描获得的指纹称为独立验证。

同一台机器使用固定的 `npu_<IP>_ed25519` 文件名。生成前检查私钥和公钥是否都存在；已存在时复用，只有一份文件时报告异常，绝不覆盖或重新生成。私钥存放在仓库和共享目录之外，仅当前用户可读；不要把私钥、口令或完整凭据写进回复、日志或 Git。用户重复点击“一键检测 NPU”时，已有 `key_path` 的机器直接检测，不再生成密钥。

用已授权的登录方式为目标账号安装公钥：创建 `~/.ssh`（权限 700），在 `~/.ssh/authorized_keys` 中仅追加尚不存在的公钥（权限 600），保留原有条目。命令行操作可用 [scripts/enroll_ssh_key.py](scripts/enroll_ssh_key.py) 逐台执行，传入 IP、用户名、现有私钥路径及可信 `--host-key-sha256`；脚本交互读取当前密码，安装后以仅私钥方式验证登录。需要用应用虚拟环境中的 Python 运行脚本。失败的机器不标记成功。不要自动修改 `sshd_config`、root 登录策略或 sudoers。

密钥可在密码变更后继续使用，但只在服务器保留对应公钥、允许公钥认证且私钥未被撤销或丢失时有效；不能承诺“永久”。

## 启动和验证

设置服务进程环境变量 `NPU_CONFIG_FILE` 为上述配置绝对路径，用虚拟环境 Python 启动 `npu_card_monitor.py`，工作目录为应用目录。服务 URL 为 `http://127.0.0.1:8765/`。

启动前检查端口。已有本应用服务且配置一致时复用；加载新配置或代码时，仅重启已确认属于本应用的进程。其他服务占用端口时报告冲突，不终止它。

Windows 用 `Start-Process -WindowStyle Hidden` 启动，传入带正确引号的脚本路径，并通过 `$env:NPU_CONFIG_FILE` 让子进程继承配置路径。其他系统使用适当的后台进程机制并记录进程标识。需要日志时放在仓库外的本机临时目录。

有限次数轮询页面 HTTP 200；检查 `/api/config` 返回的机器数量和类别，不输出完整响应（含密码）。确认成功后用浏览器工具打开 URL，报告应用位置、配置路径和服务状态。

用户类别下拉框统一筛选机器列表和卡状态；检测只针对选中类别。网页一键检测可能在用户确认指纹后安装公钥；仅请求启动应用时不自动扫描。

总览上条是 HBM 空闲比例，下条是计算利用率。详情含进程、PID、用户、显存和运行时长，以及可展开的命令、容器信息。进程退出或权限不足时字段可能未知。启动命令可能含敏感参数，不对外发布原始查询结果。
